Architecture Decision

Why Python + Django?

The challenge allowed any stack. Choosing the right tool for the scope and timeline IS architectural thinking — this was my BA decision.

  • ✓
    Batteries included — admin, ORM, auth, forms, URL routing all built-in. No extra libraries.
  • ✓
    SQLite — zero setup — database is one file. Clone and run in 2 minutes.
  • ✓
    Readable Python — AI-generated code is easy to review and validate. I can explain every line.
  • ✓
    Right for the timeline — Django delivers faster than Java + Spring Boot for this scope.
Java + Spring Boot ✗

Our App vs Spring PetClinic

What I Built Better

Spring PetClinic ✗

No Security — Zero Login

Anyone who opens the app sees ALL owner names, addresses, and phone numbers. No authentication. No protection. Completely public.

Our App ✓

Login Required + Auto Logout

Owner data protected behind staff login. Visiting home page auto-logs out the session. Session expires after 1 hour. CSRF protection on every form.

Spring PetClinic ✗

Complex Setup

Requires Java JDK, Maven, JVM, Spring Boot. 5–10 minutes to build. Needs separate database server configuration.

Our App ✓

Zero Setup — Runs in 2 Minutes

One command: pip install django. SQLite needs no installation. Anyone can clone and run immediately.

"Security was not in the requirements — I identified the gap and fixed it. That is BA thinking applied to engineering."
Non-Functional Requirements

NFR-001 to NFR-007 — Proof in Code

NFR-001 Maintainability

Separate files each with one job: models.py views.py forms.py templates/ — nothing mixed.

NFR-002 Testability

17 automated tests in tests.py.
Run: python manage.py test clinic
Result: 17 passed ✓

NFR-003 Reliability

Every view uses get_object_or_404() — wrong URL shows clean 404 page. App never crashes.

NFR-004 Security

@login_required on all owner views. csrf_token on every form. Session expires on browser close.

NFR-005 Observability

Django logs every request to terminal in real time: GET /owners/ 200 POST /owners/new/ 302

NFR-006 Performance

prefetch_related('specialties') — one database call instead of one per vet. Prevents N+1 queries.

NFR-007 Documentation → README.md + ARCHITECTURE.md + API.md + AI_USAGE.md — all in GitHub.
